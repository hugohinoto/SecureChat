# SecureChat 保存暗号鍵ローテーション手順

## 鍵の形式

- `APP_DATA_ENCRYPTION_KEY` は既存の v1 鍵として維持します。
- `APP_DATA_ENCRYPTION_KEY_V2` 以降は世代ごとに別のCloudflare Worker Secretとして登録します。
- `APP_DATA_ENCRYPTION_ACTIVE_VERSION` は新規暗号化に使用する世代番号です（未設定時は v1）。
- 暗号文は `enc:vN:` の形式で世代を持ち、復号時はその世代の鍵を選択します。
- 旧世代の鍵は、その世代のデータが残る限り必要です。

## v1 から v2 への移行

1. 現在の `APP_DATA_ENCRYPTION_KEY`（v1）を変更・削除しないでください。
2. Cloudflare Worker の Production Secrets に、新しいランダムな32バイト以上の `APP_DATA_ENCRYPTION_KEY_V2` を追加します。v1とは別の値にします。
3. `APP_DATA_ENCRYPTION_ACTIVE_VERSION=2` を設定し、Workerをデプロイします。
4. 新規データは v2 で暗号化されます。Cronが5分ごとにお知らせ最大10件、監査ログ最大20件をv2へ再暗号化します。
5. 管理画面のセキュリティ診断で「お知らせの暗号化」「監査ログ詳細の暗号化」の未移行件数がゼロになるまで待ちます。データ量によっては複数回のCron実行が必要です。
6. バックアップを確認し、代表データの読み出し・復号テストを行います。
7. 移行完了を確認するまでは v1 鍵を削除しないでください。完了後も、復旧期間を設けて安全に保管してから廃止します。

## ロールバック

移行中に問題が発生した場合は、v1鍵とv2鍵の両方を保持したまま `APP_DATA_ENCRYPTION_ACTIVE_VERSION=1` に戻します。v2で暗号化済みのデータも残るため、v2鍵を削除してはいけません。原因を調査し、両方の鍵を保持して復旧してください。

## 注意

- Secretの値をGitHub、チャット、ログへ貼らないでください。
- 鍵の値を紛失すると、その鍵で暗号化されたデータは復号できません。
- 鍵の削除は移行完了件数だけで判断せず、バックアップと復号検証を必須にします。
- この機能は保存データ暗号化の鍵世代管理です。チャットのE2EE公開鍵認証や前方秘匿性を実装するものではありません。
