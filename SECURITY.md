# Security Policy

## Supported versions

Security fixes are currently prepared for the latest code on the `main` branch. There is no promise of security fixes for older commits, forks, or deployed instances that have not been updated.

## Reporting a vulnerability

**Please do not report suspected vulnerabilities in public GitHub Issues, pull requests, discussions, or social media.**

If GitHub's private vulnerability reporting is enabled for this repository, use the **Report a vulnerability** action on the repository's Security tab to submit a private report.

If that option is unavailable, contact the repository owner through the contact method shown on the owner's GitHub profile and ask for a private channel before sending technical details. Do not include exploit payloads, credentials, personal data, or production user data in an initial public message.

Please include, where possible:

- A concise description and the affected component or commit.
- The impact and realistic attack prerequisites.
- Reproduction steps or a minimal proof of concept that does not access or alter other users' data.
- Any suggested mitigation.

## Coordinated disclosure

Please allow the maintainer a reasonable opportunity to acknowledge, investigate, and prepare a fix before public disclosure. Do not access, modify, or retain data that does not belong to you; do not disrupt service; and stop testing if you encounter real user data.

This project is a work in progress. A security report or fix does not mean that the application has been independently audited or is suitable for handling sensitive information.
